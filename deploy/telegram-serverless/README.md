# Предложка на Telegram Serverless

Telegram сохраняет обновления во встроенной SQLite. Обработчик личных сообщений
и сообщений каналу собирает черновик, сохраняет его и отправляет инструкцию или
подтверждение с номером. В журнал также попадают правки сообщений и нажатия
редакционных кнопок. GitHub Actions импортирует записи через `tgcloud run` с
последней сохранённой позиции. Действующие проверки и обработчики редакции
применяются после импорта.

## Локальная проверка

Из корня репозитория:

```sh
node --test deploy/telegram-serverless/tests/intake.test.mjs
pytest -q tests/test_serverless_intake.py tests/test_reader_intake.py tests/test_owner_review_intake.py
```

Снятие состояния из проверенной резервной копии SQLite:

```sh
python -m relocant_media.ops.serverless_snapshot /private/editorial.sqlite3 /private/intake-seed.json
```

Файл содержит личные сообщения, вложения, номера черновиков и квитанции Telegram.
Модуль переноса принимает его только в отдельном сеансе CLI. Размещайте файл
вне репозитория и передавайте через закрытый контур.

## Проверка с Telegram после допуска к бете

1. Открыть Serverless отдельного тестового бота в BotFather. Привязать CLI версии
   `@tgcloud/cli@0.2.0` через его интерактивный `login`. Убедиться, что привязка
   относится к тестовому боту и у него есть право управлять сообщениями тестового канала.
2. В тестовом проекте развернуть схему и применить только добавочные миграции.
   Для переноса и чтения очереди временно копировать `tools/transfer.js` в
   `tgcloud/endpoints/transfer.js` отдельного рабочего каталога для команды
   `tgcloud run endpoints/transfer`. Код этой операции не входит в развёртывание.
3. Загрузить тестовый снимок с ID тестового канала. Проверить устойчивость очереди и
   ответов при нескольких сообщениях подряд, двух повторных доставках, правке,
   фото и видео. В Telegram измерить время до инструкции и подтверждения для обоих
   входов. Проверить те же действия на ранее открытом черновике и на старой
   редакционной кнопке. Сохранить результат импорта и проверить повтор после перезапуска.
4. Перед переключением рабочего бота зафиксировать последний проверенный
   снимок и журнал квитанций. Сохранить открытые черновики с прежними номерами,
   принять накопившиеся обновления и сверить редакционные нажатия. В Actions отдельно
   настроить `TGCLOUD_TOKEN` и включить `ACTIONS_SERVERLESS_INTAKE_ENABLED` в рамках
   переключения. Вызов `tgcloud webhook sync` меняет способ доставки сразу для всего
   бота. Выполнять его без сброса ожидающих обновлений.

При возврате к опросу сначала импортировать последний журнал Serverless и проверить
снимок редакции. Затем вернуть доставку через Bot API `deleteWebhook` с
`drop_pending_updates=false` и переключить источник входящих событий в Actions.

[Документация Telegram Serverless](https://core.telegram.org/bots/serverless)
