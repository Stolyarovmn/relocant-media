# Разбор фиксированной старой очереди

Ручной режим `drain` использует существующий `Editorial Actions`, канонический CAS,
SQLite, редакционный пайплайн и проверенную доставку. Он обрабатывает прежние
материалы без нового сбора новостных лент. Состав очереди фиксируется по серверному
`ingested_at <= drain_before` и сохраняется в закрытом журнале кампании вместе
с контрольной суммой списка. Новые поступления не расширяют эту кампанию.

Время публикации источника не определяет состав кампании. Поздно обнаруженная старая
статья остаётся новым поступлением. Доказанная замена первоисточника наследует
принадлежность исходному материалу, срок и бюджет.

Параметры ручного запуска:

| Вход | Значение по умолчанию | Предел |
|---|---|---|
| `mode` | `drain` | Только ручной запуск либо его ограниченное продолжение |
| `drain_before` | Обязательный ISO момент UTC | Не позднее времени запуска |
| `drain_max_attempts` | 10 | До 30 сохранённых попыток за запуск |
| `drain_max_seconds` | 300 | До 900 секунд между проверками бюджета |
| `drain_runs_left` | 1 | До 200 запусков одной кампании |

Лимит времени кооперативный: текущая попытка завершается штатно, затем сохраняется
снимок. Неизвестная отправка не прерывается ради следующей пачки. Отдельные попытки
проверки отказа и полной повторной обработки учитываются отдельно. Ограничения
каждого материала, сроки актуальности, риск, права читателя, карты, источники и
независимые ревью сохраняются. Новый режим не создаёт одобрение человека.

Обычный выпуск сохраняет прежнее распределение мест; при разборе старого хвоста
все пять мест пачки доступны наступившим проверкам отказов и повторам. За весь
запуск разрешены не более двух попыток доставки. Приём новых сообщений продолжает
использовать прежний самостоятельный маршрут.

Каждый запуск возвращает канонический указатель в подтверждённое состояние после
проверенного снимка. Ожидание следующего срока выполняется в отдельном задании
продолжения без блокировки состояния. Оно передаёт тот же cutoff и уменьшенный
бюджет. Продолжение даёт другим очередям возможность получить писатель; порядок
выделения ресурсов GitHub не гарантирует точное время старта. Задание ожидания
оставляет запас времени до своего предельного таймаута.

Повтор уже завершённого шага не повторяет модель и доставку. Перезапуск не
обнуляет бюджеты материалов. После исчерпания лимита кампании незавершённые
материалы сохраняют свои обычные следующие шаги и сроки; они не блокируются
только ради нулевого счётчика.

`PRIMARY_OK` означает отсутствие подходящих кандидатов в конкретном проходе.
Завершение кампании определяется отдельно: каждый исходный материал должен иметь
подтверждённую публикацию либо окончательную блокировку. Дубли, отложенные повторы
и ожидание резерва остаются видимыми до конечного решения. Некорректная квитанция
остаётся нерешённой сверкой; автоматической повторной отправки нет.

Закрытый `drain-report.json` и журнал кампании содержат итог, причины остановки,
следующий срок и ограниченный список примеров. Полный остаток учитывается при
расчёте количества и следующего срока. Состав кампании, документы и история
попыток не передаются в публичную проекцию; продолжение получает только
управляющий признак и ограниченную задержку.

Для проверки результата используйте локальный read-only аудит двух завершённых
immutable снимков. Очистка означает завершение ожиданий; опубликованные и
заблокированные записи сохраняются для аудита.

По прямому решению владельца режим `drain-close` закрывает остаток уже существующей
кампании с тем же `drain_before`. Он не создаёт новый состав, не вызывает модель,
не собирает источники и не отправляет сообщения. Применяется причина
`owner_closed_backlog`; прежние окончательные решения и подтверждённые публикации
сохраняются. Неизвестная доставка сохраняет транспортное состояние и получает
причину сверки. Исходные записи, бюджеты и квитанции не удаляются.

Закрытие использует общий канонический писатель, проверенный снимок и CAS.
Перед записью проверяются состав и связи замены источников. Общая переоценка
других материалов до и после этого режима не запускается. Сохранённый маркер
решения запрещает последующим продолжениям этой кампании вновь обрабатывать
материалы. Повторное закрытие идемпотентно. Новые поступления вне состава кампании
продолжают обычный маршрут.

Публичная панель учитывает окончательную блокировку и для материалов, которые
ещё не имели редакционного запуска. Полностью закрытые события отображаются
среди отложенных без автоматического повтора. Смешанный сюжет сохраняет активный
новый материал; неопределённая доставка имеет приоритет для сверки. Успешная
публикация требует `sent` и положительного целочисленного Telegram ID.
