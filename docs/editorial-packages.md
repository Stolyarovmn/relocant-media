# Импорт редакционных пакетов без внешнего AI API

Пакет готовят редактор и два независимых проверяющих средствами подписки. Импорт
не вызывает Gemini, другие AI API или Telegram. Доступ к исходной статье проверяют
проверяющие; флаг `live_source_checked` является их явным свидетельством, а не
результатом сетевой проверки импортёра. Строковые идентификаторы проверяющих
не являются криптографической аутентификацией: пакет должен поступать от доверенного
локального редакционного процесса.

Предварительная проверка работает без БД и секретов:

```powershell
relocant-package --package work/editorial-package.json
```

Запись в настроенную БД выполняется только явно:

```powershell
relocant-package --package work/editorial-package.json --persist
```

После записи по умолчанию выполняется `dry-run` доставки с повторной проверкой
редакционных ограничений. Для проверки сериализации Bot API без Telegram:

```powershell
relocant-package --package work/editorial-package.json --persist --transport fake
```

`fake` требует `--persist` и использует только `httpx.MockTransport`, фиктивный
токен и фиктивный chat id. Обе разновидности не вызывают AI, не используют реальные
Telegram credentials и не расходуют квитанцию: `delivery_status=pending`,
`staging_message_id=null`. Повторный запуск не создаёт новый черновик.
Пакеты, заблокированные политикой, сохраняются без имитации доставки.

Импорт запрещён при `APP_ENV=prod` и `production`. Он создаёт `EditorialRun` и
черновик `Post`, сохраняя полный пакет и его SHA256 в дополнительных полях
`outcome._package` и `outcome._package_sha256`. Новая миграция не нужна.
Состояние доставки остаётся `pending`, Telegram message id не создаётся.
Команда не имеет флага реальной отправки.

## Формат версии 1

Авторитетная схема — `EditorialPackage.model_json_schema()` из
`relocant_media.ai.package`. Все вложенные структуры строгие: неизвестные поля
запрещены, строки вместо чисел и логических значений не приводятся автоматически.

Поля верхнего уровня:

- `version`: число `1`.
- `policy_version`: строка `subscription-editorial-v1`.
- `city`, `raw_item_id`, `source_id`, `article_id`: город, числовой PK `RawItem`,
  идентификатор источника и его `RawItem.external_id`.
- `urgent`: логическое значение, по умолчанию `false`.
- `evidence`: точный снимок `source_id`, `url`, `title`, `body`, `published_at`.
- `outcome`: существующий структурированный редакционный результат с обязательными
  `ranking`, `claims`, `verification`, `draft`, `status`, `reason`, `confidence`.
- `reviews`: ровно два объекта проверок, один с `role=facts`, второй `role=utility`.

Каждая проверка содержит `reviewer_id`, `role`, `source_id`, `article_id`,
`draft_sha256`, `context_sha256`, `reviewed_at`, `verdict` (`approve`, `hold`, `reject`), `score`
(целое 0–100), `flags` (массив строк), `live_source_checked`.
У `reviewed_at` обязателен часовой пояс. Идентичности после удаления внешних
пробелов и приведения регистра должны различаться. Отсутствующий
`live_source_checked` считается `false`.

`draft_sha256` — 64 строчные шестнадцатеричные цифры SHA256 байтов UTF-8
канонического JSON **всего** draft: `title`, `body`, `claim_ids`.
Используется `json.dumps(draft, ensure_ascii=False, sort_keys=True,
separators=(",", ":"))`, без завершающего перевода строки. Строки и порядок
`claim_ids` не нормализуются. Функция `draft_sha256()` вычисляет этот формат.
Изменение хотя бы одного символа требует обеих новых проверок.

`context_sha256` вычисляется тем же способом для
`package.model_dump(mode="json", exclude={"reviews"})`: **все** поля пакета,
кроме массива reviews, включая значения по умолчанию, входят в хэш. Это связывает
проверки с evidence, claims, verification, полной ranking/category, draft,
городом, source/article/raw id, urgent, status/confidence и обеими версиями.
Проверяющие используют `context_sha256()` после подготовки окончательного
пакета. Любое изменение контекста требует двух новых проверок даже при
неизменном тексте draft. Хэш не включает самих reviews, чтобы исключить циклическую
зависимость.

## Правила допуска

Импорт повторно проверяет точные цитаты в evidence, уникальность claim ids,
полноту verification, подтверждение существенных утверждений и ссылки draft
только на подтверждённые claims. Нарушение этих контрактов отклоняет пакет.

Самостоятельно заявленные `ready` и `should_process=true` недостаточны.
В `ready` остаются только `transport` и `events` с выбранным материалом,
достаточной минимальной уверенностью по общей политике и двумя `approve`:
обе оценки >=75, оба массива flags пусты, оба `live_source_checked=true`.
Будущие проверки не принимаются. Для `urgent` проверки действуют 2 часа,
для остальных — 24 часа. Несоблюдение условий переводит заявленный `ready`
в `human_review`. Заявленные `human_review`, `blocked`, `skipped` не повышаются.
Категории обязательной человеческой проверки никогда не становятся ready.

При последующем вызове существующего staging publisher срок проверок и правила
пакета проверяются заново; устаревший пакет не может отправляться автоматически.
Текущие `Post.title` и `Post.body` также должны точно совпадать с проверенным draft:
редакторское изменение блокирует доставку до повторной проверки.
Существующие правила неизвестного исхода доставки сохраняются.

Импорт блокирует `RawItem` транзакционно и сравнивает источник, external id,
город и полный снимок статьи с БД. Совпадающий пакет импортируется идемпотентно,
не сбрасывая квитанцию доставки. Другой пакет, изменившаяся исходная статья,
изменившийся сохранённый черновик или существующий результат другого процесса
вызывают конфликт. Новый пакет не перезаписывает предыдущую редакционную работу.

## Импорт и событие после editorial v2

Новый импорт применяет ту же event-level дедупликацию, что и обычный prepare:
повтор уже рассмотренного события под другим URL отклоняется до создания поста.
Проверка и создание результата сериализуются транзакционной PostgreSQL-блокировкой
на город, общей для prepare и импорта. Это закрывает одновременный импорт разных
raw IDs одного события; commit/rollback освобождает блокировку автоматически.
Старые строки без сохранённых canonical URL/SHA256 проверяются по вычисляемым
отпечаткам; отсутствие полей не является основанием пропустить сравнение.

В EditorialRun сохраняются event_key, документы события с raw IDs и политиками
источников, editorial_rule_version=belgrade-editorial-v2. Политики применяются
ко всему событию, включая high_risk дополнительных источников.

Пакет версии1 связывает ревью только с основным документом. Если найдены
дополнительные документы того же события, такой пакет не получает автоматический
ready: причина package_requires_event_bundle_review. Это не новая версия формата
пакета и не подтверждение проверки остальных документов. Нужна подготовка с полным
контекстом и соответствующими независимыми ревью; нельзя удалять документы или
менять source policy ради допуска.

Совпадающий повторный импорт сохраняет исходный снимок и состояние доставки,
в том числе исторических результатов без documents. Он не обновляет доказательства
и не сбрасывает sending/uncertain/sent. Перед доставкой новые bundle-снимки
проверяются существующим EditorialService.
