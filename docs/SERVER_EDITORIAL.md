# Редакция на выделенном сервере

Команда `python -m relocant_media.ops.server_cycle --output <новый каталог>`
использует существующую SQLite из DATABASE_URL и существующие GEMINI_API_KEY,
GEMINI_MODEL. Она не создаёт схему и не запускает миграции. Секреты размещаются
в `/etc/relocant-media.env`, root0600; состояние принадлежит отдельному пользователю
relocant. Копирование личной MTProto-сессии не требуется и запрещено.

Сбор включает две штатные городские ленты и транспортный раздел за последние
семь дней. Ранее собранный хвост остаётся в БД. Устойчивое окно primary_cycle
обрабатывает максимум два новых кандидата за запуск. Ограниченные источники
сохраняются как human_review без AI-вызовов. При смене источника остаются
source_revision и исходные квитанции; автоматического принятия поправок нет.

Gemini готовит структурированный черновик. Перед допуском выполняются две
отдельные stateless-проверки той же моделью: facts и utility. Каждой передаётся
полный окончательный контекст v2 без чужого вердикта. Перед каждым вызовом
первичные документы заново читаются по HTTPS и точно сверяются. Фактическое
независимое посещение мест не заявляется. Рубрика, причины, флаги и хэши
сохраняются в review-audit-<rawID>.json. Score полезности вычисляется из рубрики.
Любое изменение контекста, политики источника или срока ревью блокирует отправку.

Штатные package/source/category guards сохраняются. После префикса
`[тестовый запуск]` и двух действительных одобрений пакет импортируется.
EDITORIAL_SEND_ENABLED по умолчанию выключен. Отдельный ChannelPublisher жёстко
привязан к согласованному каналу; staging-издатель не используется для его обхода.
Автоматические исправления и удаления старых сообщений этот цикл не выполняет.

Доставка ограничена двумя постами за запуск. До Bot API сохраняется sending;
после успешного ответа Post.telegram_message_id и sent сохраняются вместе.
Неизвестный исход, включая аварийный сбой между отправкой и фиксацией, запрещает
автоматический повтор: sending/uncertain требуют сверки. Никаких retry отправки.
После подготовки делается последняя живая сверка и повторяются guards.

systemd units в deploy/server запускают цикл раз в три часа, под отдельным
пользователем, с лимитами памяти450МБ/CPU70%, без входящих сетевых портов.
Systemd и файловая блокировка защищают от перекрытия запусков на одном хосте.
Перенос требует сверки снимка и квитанций и отключения прежнего локального
писателя; нельзя синхронно эксплуатировать две копии SQLite.

Каждый завершившийся проход пытается создать проверенный локальный снимок,
даже после ошибки AI/сбора/доставки. remote_backup=pending честно означает, что
файл ещё не подтверждён в Drive. Серверной авторизации Drive в этом изменении нет.
Внешний процесс приложения получает снимки по SSH и сохраняет в закрытой Drive
с проверкой восстановления. Без работающего приложения этот внешний этап
и подписочный ChatGPT fallback не выполняются. Сервер не использует чужой
API-ключ OpenAI и не выдаёт Gemini за ChatGPT.

PRIMARY_FAILED/SERVER_FAILED и fallback_required — основания для внешнего
ChatGPT-процесса прочитать серверный журнал и подготовить проверенный пакет,
сохранив ту же каноническую БД и защиту от повторов. Если источник/AI недоступны,
серверный таймер продолжает попытки в следующие запуски; сообщения об ошибке
не включают содержимое исключений API или секреты. Отсутствие отчёта после
принудительной остановки не означает успех. Перед включением проверить
getMe/getChatMember, реальную генерацию и один проход с выключенной отправкой.
