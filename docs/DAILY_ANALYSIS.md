# Ежедневный операционный статус

Существующий `daily-analysis` больше не заглушка: ручной workflow читает только
`dashboard-data/latest.json` из `newsroom-data` и создаёт JSON/Markdown artifact
`daily-status-<run>-<attempt>` и GitHub Step Summary. Код исполняется из основной
checkout; файлы ветки данных никогда не исполняются. Доступ только `contents: read`,
БД, Drive, Telegram, модель и секреты не требуются.
CLI сначала объединяет снимок с актуальным реестром через общий безопасный merge:
историческая пустая запись Нови-Сада не считается запущенной редакцией. Если checkout
данных завершился ошибкой, `--snapshot-unavailable` игнорирует любые частично полученные
байты и даёт unavailable, даже если файл успел появиться. Расписание не включено,
дублирующая автоматизация и отправка отчёта владельцу не создаются.

Дата отчёта и отображение времени — Europe/Moscow. Время создания отчёта отдельно
от времени наблюдения БД. Снимок старше шести часов или с будущей датой помечается
`stale`; отсутствие наблюдения — `unavailable`. Сборка отчёта не освежает снимок.

Отчёт показывает состояния очереди, повторяющиеся reason codes только в возвращённой
выборке и 3–5 следующих действий. `held` остаётся удержанием, а не отклонением.
Неизвестные показатели остаются null. Суммарный `sent` не считается суточным числом
публикаций: публичный экспорт не содержит достоверного времени отправки. Дата статьи
не заменяет его. Повторы причин не доказывают временной тренд или обучение на аудитории.
Продвижение, метрики аудитории, комментарии и входящие обращения недоступны в этом
источнике и явно обозначены как неизвестные. Рекламные действия не выполняются.

Локальный безопасный запуск:

```sh
python -m relocant_media.ops.daily_analysis \
  --snapshot /path/to/public/latest.json --output /tmp/daily-status
```

Для полного суточного отчёта потребуется отдельно подключить подтверждённые агрегаты
доставок с временем отправки, продвижения и аудитории, не раскрывая приватную предложку.
Существующий `analytics.report` работает с БД и не переиспользуется здесь: он требует
другого источника данных и не должен выдавать неполную публичную проекцию за полную БД.
