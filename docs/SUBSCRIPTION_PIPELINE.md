# Автоматический сбор для редакции без AI API

Два отдельных шага соединяют источники с редакционным навыком: сбор сохраняет
сырьё в staging PostgreSQL, экспорт выбирает ещё не обработанные кандидаты.
Оба шага требуют явно заданных `APP_ENV=staging` и `DATABASE_URL`, не читают
`.env`, не создают Gemini/Telegram-клиенты и не запускают MTProto.

```sh
python -m relocant_media.ops.collect_cli --city belgrade --source-id cukarica_news
python -m relocant_media.ops.candidates_cli --city belgrade \
  --since 2026-10-18T12:00:00+00:00 --until 2026-10-19T12:00:00+00:00 \
  --limit 5 --output /absolute/path/new-run/candidates
```

Команды выполняются из корня репозитория. Каталог экспорта должен быть новым.
Экспорт читает БД в согласованной транзакции только для чтения. Окно применяется
к дате публикации: начало включено, конец исключён. При восстановлении пропуска
передайте начало после последнего успешного запуска с перекрытием. Отсутствующая
дата не подменяется сегодняшней: такие записи перечислены отдельно. При `truncated`
есть оставшиеся кандидаты; экспорт сам не считает их просмотренными. Перенос
контрольной точки допустим только после обработки всего окна или явного сохранения
оставшейся очереди; нельзя терять хвост из-за лимита пяти материалов.

`manifest.json` версии 2 содержит точные evidence, исходные идентификаторы и SHA256
снимка, а также `event.key`, `member_raw_item_ids`, `source_ids` и evidence участников.
Кандидат представляет событие: `candidate_count` и `eligible_count` считают события,
а не исходные статьи. Дедупликация использует canonical URL, нормализованный SHA256
текста и ограниченное сходство заголовков между разными источниками в окне 48 часов.
Уже рассмотренное событие исключается и при появлении другого URL/источника.
Рецензентам
всё равно нужно самостоятельно открыть актуальные источники. Хэш evidence экспорта
не является хэшем контекста готового редакционного пакета и не доказывает ревью.

При изменении уже проверенного raw item сбор не перезаписывает сохранённые
доказательства. Он регистрирует `ReviewedEvidenceChangedError`, переводит
редакционный результат и неопубликованный пост в `human_review` с причиной
`source_changed_requires_review`. Текст, пакет и квитанция доставки сохраняются;
автоматического восстановления допуска нет. Для нового состояния источника
нужны явная новая версия и новые проверки. Одинаковые URL новых кандидатов
схлопываются до подсчёта и лимита; выбирается одна запись детерминированно.

После отбора редакционный навык готовит русский текст и получает две независимые
проверки. Пакет создаётся по [editorial-packages.md](editorial-packages.md), затем:

```sh
python -m relocant_media.ops.package_cli --package /absolute/path/package.json \
  --persist --transport fake
```

Отсутствующее, просроченное или неуспешное ревью нельзя заменять одобрением.
`fake` проверяет сериализацию Bot API без внешнего HTTP и не создаёт квитанцию
публикации. Реальная отправка остаётся выключенной. Экспортёр не генерирует текст
и не выдаёт собственные оценки за независимых рецензентов.

## Источник Чукарицы

`cukarica_news` читает главную официального сайта и полные статьи. Он заменяет
ручное извлечение для следующих выпусков; прежний `cukarica_official_manual`
остаётся отдельным историческим источником. Ссылка фестиваля655 уже обработана,
поэтому повторно не предлагается экспортёром. Поддерживаются только проверенные
HTTPS-адреса этого муниципалитета. Изменение шаблона или недоступность статьи
считается сбоем сбора, а не пустым успешным выпуском. `auto_publish=false` в
реестре отражает режим источника; разрешение публикации этим файлом не создаётся.

Регулярный запуск вызывает эти команды до веб-поиска, затем использует поиск
для расширения тем и проверки полных первоисточников. Наличие команды ещё не
означает успешный запуск по расписанию: это подтверждается отдельной записью
в журнале и сохранёнными артефактами конкретного выпуска.

## Контракт редакционного навыка после v2

До отбора проверяйте `version == 2`; неизвестный формат требует явного сбоя,
а не молчаливого чтения как v1. Сохраняйте идентичность события и ссылки на все
исходные raw items. Для проверки передавайте весь `event.evidence`, а не только
`candidate.evidence`. Наличие нескольких документов не доказывает независимость
первоисточников и не заменяет два независимых ревью готового текста.

`evidence_sha256` по-прежнему относится к основному документу кандидата, а не ко
всему событию и не к готовому редакционному пакету. Не подставляйте его вместо
`context_sha256`. Экспортный bundle не копируйте механически в пакет: соблюдайте
модель пакета и проверяйте текущие документы. `EditorialService.prepare` сам
собирает доказательства из БД и сохраняет bundle в `EditorialRun.evidence.documents`
с raw IDs и политиками источников; перед доставкой документы сверяются повторно.

У новых результатов и постов `editorial_rule_version=belgrade-editorial-v2`.
`legacy-v1` сохраняйте как историю: не переименовывайте старые результаты ради
однородной статистики. В журнале и аналитике различайте версии правил.

Нельзя снимать `auto_publish=false`, `high_risk` или требование официального
источника ради успешного preview. `human_review`/`blocked` — допустимый результат
безопасного прогона; fake-одобрение не является независимым фактчеком.

Этот контракт не изменяет маршрутизацию Gemini primary → ChatGPT fallback,
расписание каждые 3 часа или разрешения Telegram/рекламы. При расхождении
локальной конфигурации с указанным режимом фиксируйте расхождение; не включайте
другое расписание и не создавайте дублирующий запуск автоматически.
