# Проверяемый перенос и восстановление

`python -m relocant_media.ops.sqlite_transfer --output <новый каталог>` требует
явных APP_ENV=staging и DATABASE_URL PostgreSQL. Это чтение исходной базы,
а не её изменение или автоматическое переключение обработчиков.

Сначала берётся городской writer lock, затем отдельный REPEATABLE READ / READ ONLY
снимок. Проверяются точные наборы таблиц и столбцов; неизвестное поле нельзя молча
потерять. Копируются все модели в порядке внешних ключей с исходными PK, JSON,
временем UTC, текстами, версиями правил и всеми состояниями доставки, включая
sending/uncertain/sent. Старые проверки не переоцениваются и не продлеваются.

Все строки каждой таблицы сравниваются по упорядоченному каноническому SHA256
до подтверждения. Сохраняются уровни PostgreSQL-последовательностей в SQLite
AUTOINCREMENT, чтобы удалённые ранее номера не использовались снова. Проверяются
схема, целостность и внешние ключи. Только затем появляется transfer.json с
verified=true и activated=false. Новый каталог не перезаписывает старый.

Городской lock не останавливает всех возможных писателей статистики, предложки
или иных сервисов. Поэтому для реального переключения нужно отдельно подтвердить
остановку всех обработчиков, сравнить финальную копию и изменить единственный
указатель рабочей БД. Исходная PostgreSQL сохраняется для сверки/отката и после
переключения не должна параллельно принимать редакционные записи.

Снимок для Drive создаётся sqlite_backup_cli. После загрузки базы отдельно
загружается манифест с Drive file ID, SHA256, размером, версией и поколением.
Папка остаётся закрытой; предыдущие версии не удаляются. Отсутствие подтверждённого
манифеста запрещает считать файл готовым к восстановлению.

`ops.sqlite_restore.restore(snapshot, manifest_path, output)` восстанавливает
только в новый каталог. SHA256 и размер проверяются до копирования, после копирования
повторно проверяются байты, схема и целостность. Неверный снимок не активируется.
Функция создаёт restore.json с activated=false; изменение рабочего указателя
выполняется отдельно после проверки содержимого и квитанций. Автоматическая
распределённая синхронизация нескольких хостов через Drive этим не реализуется.
