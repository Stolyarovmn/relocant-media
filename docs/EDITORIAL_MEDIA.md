# Иллюстрированные редакционные выпуски

Для события сначала ищите материалы организатора и проверяйте место, год,
автора и условия использования. Доступная статья не подтверждает разрешение
скачать её фотографии для своего альбома. Ссылка и собственный краткий пересказ
не требуют превращать фотографии в наши вложения. Цитирование оценивается по
применимому праву и цели, а не по универсальному проценту материала.
Если происхождение или основание использования изображения не подтверждено,
оставьте ссылку на оригинал либо подготовьте собственную информационную карточку.
Не выдавайте иллюстрацию или архив за репортаж с текущего события.

`MediaRelease` связывает исходный raw item/post, канонический SHA256 редакционного
пакета, точную подпись, получателя и 1–10 локальных PNG/JPEG. Каждое изображение
имеет SHA256, происхождение, основание прав, подтверждение и атрибуцию. Для фото
нужен подтверждённый год и явная подпись с годом; атрибуция включается в caption.
Булево подтверждение прав — свидетельство редакционной проверки, а не автоматический
юридический вывод из наличия URL. Не выставляйте его без основания.

Два независимых медиа-ревью проверяют факты и полезность готовых изображений
вместе с подписью. Аттестация содержит хэши каждого файла, caption и всего контекста
без reviews (UTF-8 canonical JSON, ensure_ascii=false, sorted keys, separators=(',',':')).
Обе проверки действуют максимум24часа; текстовая редакционная политика проверяется
заново и сохраняет более короткие ограничения срочного исходного пакета.
Замена изображения, подписи, порядка, происхождения, прав или target требует
нового совпадающего контекста. Редактор не имитирует недоступного рецензента.

По умолчанию команда проверяет реальные multipart-запросы через fake HTTP:

```sh
python -m relocant_media.ops.media_cli --release /run/release.json \
  --assets /run/images --receipts /persistent/staging-media-receipts
```

Требуются явно заданные `APP_ENV=staging`, `DATABASE_URL`, numeric
`TELEGRAM_STAGING_CHANNEL_ID` и `TELEGRAM_CHANNEL_ID` для исключения основного канала.
`.env`, AI-клиенты и MTProto не загружаются. Fake не расходует реальную квитанцию.
Только после отдельного разрешения владельца на конкретный тестовый выпуск:

```sh
python -m relocant_media.ops.media_cli --release /run/release.json \
  --assets /run/images --receipts /persistent/staging-media-receipts \
  --transport bot-api --send-staging
```

Проверенные байты передаются в HTTP без повторного чтения изменяемого файла.
Один снимок идёт через sendPhoto, 2–10 — через sendMediaGroup с подписью у первого.
Подпись ограничена1024единицами UTF-16; сообщения не дробятся с потерей смысла.

Квитанция медиа-выпуска хранится отдельно от исходного текстового EditorialRun.
Она эксклюзивно создаётся и синхронизируется на диск ДО HTTP: sending → sent или
uncertain. Успех сохраняет все message_ids. Повтор того же release_id и хэша
возвращает квитанцию без HTTP; другой контекст с тем же ID блокируется.
При sending/uncertain повтор запрещён до сверки фактического альбома. Не сбрасывайте
исходную квитанцию текста ради повторной публикации иллюстрированной версии.

Ограничение staging: все процессы должны использовать один устойчивый каталог
квитанций. Независимые хосты/каталоги не обеспечивают общую защиту от дублей;
для такого развёртывания нужен единый реестр доставки. Потеря каталога также
теряет гарантию повторов. Каталог и release_id нельзя менять ради обхода uncertain.
Поддержка медиа не включает автоматическую публикацию ежедневной задачи.
