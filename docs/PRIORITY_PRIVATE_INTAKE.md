# Предложка первой на проверку

Решение владельца21.10: закрытые входящие получают приоритет разбора и ревью.
Приоритет не означает доверие к тексту автора, автоматическую публикацию,
платное размещение или право обойти категорию риска. Предложка не пересылается
в канал, обсуждение и форум. Ответов отправителю приёмник сам не отправляет.

## Приём и доступ

`receive_private_tips` выключен по умолчанию. Для канала-1003967014133 нужен
`can_manage_direct_messages`, явный `EDITORIAL_PRIVATE_INTAKE_ENABLED=true`,
отсутствие действующего webhook и единственный серверный обработчик под worker.lock.
Существующий webhook не удаляется, доступ не расширяется самим кодом, фильтр
allowed_updates не изменяется. При отсутствии права getUpdates не вызывается.
Незавершённые старые квитанции блокируют продвижение offset до разбора.

Приём выполняется перед сбором сайтов в штатном цикле каждые3часа, максимум100
обновлений. Дата/идентификатор Telegram не выдумываются. Квитанция и Submission
коммитятся вместе, следующий offset подтверждает только уже сохранённое.
При сбое до commit обновление остаётся для повторного получения. Native DM
принимается только после getChat с parent_chat.id нашего канала. Для отдельного
бота остаются /tip,/correction,/ad и существующий диалог сбора; city задаёт
обработчик, не текст автора. Вложения пока сохраняются только как закрытые
ссылочные идентификаторы, без скачивания и передачи модели.

Историю Bot API не восстанавливает: входящие обновления хранятся ограниченное
время. Уже существующие сообщения нельзя объявлять импортированными по одному
включению приёмника. Ранее4pending updates — только счётчик, а не4предложения;
их содержимое при проверке готовности не читалось и не подтверждалось.

## Закрытая очередь и первоисточники

Submission хранит входящие в той же канонической SQLite. Экспортируются только
счётчики и технические статусы; имена, контакты, текст и file_id остаются внутри.
Рекламные заявки не переходят в новостную очередь. Для новостей и поправок
первым шагом извлекаются прямые ссылки на уже разрешённые сайты, без query
параметров. Неизвестные домены, IP, чужой порт и credentials не запрашиваются.

Частный текст не становится RawItem, evidence bundle, claims или публичным
поисковым запросом. Сопоставление с уже собранными заголовками выполняется
локально. Полный первоисточник извлекается отдельно и проходит прежние проверки
свежести/мероприятия. Без него статус waiting_primary, а не фиктивное одобрение.
source_linked означает найденный источник для разбора, а не проверенное сообщение
автора. Эти raw IDs поднимаются выше обычного сбора при выборе кандидатов.
Событийная дедупликация и оба независимых ревью сохраняются.

## Поиск по публичным темам

Для PUBLIC Telegram-тем разрешено локальное сопоставление сербской кириллицы
и латиницы и дополнительный поиск RSS только у явно упомянутой известной
площадки. Не более2сайтов на тему и4поисковых запросов за весь проход,
с одним словом запроса. Это ограниченный поиск по доверенному реестру,
не всеобщий поиск по интернету. Он не расходует ИИ. Совпадение3значимых слов
лишь находит кандидата; официальная статья должна быть получена полностью,
а факты и связь даты с событием проверяются независимо. Частная предложка
этот внешний поиск не вызывает.

## Разнообразие и изменения опубликованного

При одинаковом приоритете первым разбирается источник с меньшим числом отправок
за24часа. Это мягкий порядок, не квота на публикацию. Приоритет предложки и
транспортных изменений выше; качество и все guards важнее разнообразия.
Просмотры и рост аудитории при этом не используются.

До10источников уже опубликованных материалов за30дней перепроверяются без ИИ.
Изменение сохраняется через штатный SourceRevision; исходное evidence и
публичное сообщение не переписываются. published-source-watch.json содержит
ID изменений и классы ошибок, без закрытых входящих. Эта часть выявляет
необходимость исправления; автоматическое редактирование старого сообщения
после ревью пока остаётся отдельным механизмом, а не разрешением из монитора.

Изменение БД после реального приёма или фиксации ревизий требует согласованного
снимка, уникального поколения закрытой Drive-копии и обратного восстановления.
Gemini primary → подписочный ChatGPT fallback и расписание не меняются.
