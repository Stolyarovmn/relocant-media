# Проверка предложки и ответы автору

Частное сообщение — указатель для редакции, не доказательство. Выдуманный слух
без источника получает waiting_primary/missing_primary, запрос деталей и ноль
вызовов ИИ. Нельзя объявлять его ложным лишь из-за отсутствия подтверждения.
Без подтверждений обычное обращение истекает через48часов и не допускается к выпуску.

Прямая ссылка проверяется отдельно разрешённым адаптером. Частный текст не входит
в RawItem, claims или evidence. source_linked — найден первоисточник, а не одобрены
все слова автора. Повод, уже имеющий EditorialRun, получает ответ already_considered;
событийная дедупликация сохраняется. Новый повод проходит обычную редактуру, два
независимых ревью и guards. Источник и категория риска не обходятся.

## Аварии и заторы

Эвристика распознаёт дорожный сигнал для запроса уточнений, а не для доказательства:
точное место, направление, время наблюдения, что человек видел лично, затруднено
движение или действительно закрыт весь проезд. Фото/видео только безопасно,
без съёмки за рулём, лиц пострадавших и чужих личных данных. Вложения пока не
скачиваются и не проверяются автоматически; их наличие не подтверждает происшествие.

Один рассказ не даёт права публиковать «проезд закрыт». Автоматическая публикация
неподтверждённых очевидцев выключена. Ищем отдельно свежие публичные подтверждения;
чужие репосты одного сообщения не являются независимыми свидетелями. Даже два
совпадающих рассказа сами по себе не обходят текущие source/category guards.
Не добавляем причины, пострадавших или виновных, которых нет в доказательствах.
Без первоисточника дорожный сигнал истекает через1час от приёма в БД.

Текущий запуск каждые3часа не подходит для обещания оперативных предупреждений:
редактор может увидеть сигнал уже истёкшим. Расписание не меняется этой доработкой.
Для оперативного режима потребуется отдельный постоянно работающий приёмник
с единственным потребителем updates и отдельной проверкой свежести.

## Закрытый ответ

Ответы включаются отдельным EDITORIAL_PRIVATE_FEEDBACK_ENABLED=true после решения
владельца. До20ответов за цикл, текст детерминирован, без ИИ и цитирования входящего.
Личный чат бота — только совпадающий с автором положительный chat_id; native DM —
только проверенный getChat.parent_chat основного канала и direct_messages_topic_id.
Публичный канал/обсуждение не могут стать адресатом. Рекламные заявки не затрагиваются.
Используется официальный Bot API sendMessage; платные отправки выключены.

Перед сетью сохраняется sending. После ответа — квитанция sent; при любой ошибке
uncertain, без слепого повтора. Зависшие sending/uncertain/blocked остаются видны
в аудите следующих циклов. Штатный вызов выполняется под worker.lock.

Ответ на запрос в личном чате бота связывается с прежним обращением только по
реальной квитанции нашего ответа и тому же автору/чату; создаётся новая версия
обращения для проверки, старая superseded. Команды /tip и /correction начинают
явное новое обращение. В native DM каждое новое сообщение сохраняется отдельно.

Регрессии: tests/test_submission_feedback.py. Реальный контроль через Telegram
использует отдельные помеченные владельцем сообщения: фиктивный слух F20261021
и официальный анонс R20261021. Они не разрешают новую публикацию. Синтетические
объекты tests не являются живой проверкой native DM или независимым фактчеком.
