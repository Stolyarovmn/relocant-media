# Облачный поиск → каноническая редакция

Владелец 26.10.2026 разрешил передавать найденные в облаке новости на штатные
проверки и публиковать прошедшие их материалы в `@eduvbelgrad`. Черновики в чате
больше не являются способом доставки результата.

## Доверенный вход

`Editorial Actions` принимает ручной `workflow_dispatch` на актуальном `main`:

- `mode=discovery`;
- `discovery_batch` — JSON версии 1, город `belgrade`, от одной до десяти HTTPS-ссылок.

```json
{"version":1,"city":"belgrade","urls":["https://www.beograd.rs/cir/beoinfo-vesti/a116374/Radovi-na-vodovodnoj-mrezi-na-opstinama-Barajevo-i-Grocka.html"]}
```

Пример выше показывает формат, а не указание повторно отправить старое событие.
Можно передавать только публичные ссылки без credentials, приватных контактов,
токенов и персональных данных. Dispatch доступен только пользователю/интеграции
с правом запуска Actions; новый неавторизованный HTTP endpoint не создаётся.

Workflow проверяет точный зелёный `main` и использует прежнюю concurrency group.
Адаптер проверяет формат до захвата состояния, восстанавливает существующую SQLite,
проверяет cutover и атомарно отмечает её `busy`. Только после этого ссылки становятся
`Submission(kind=news_tip, origin=cloud_discovery)` в той же БД. Telegram-пользователь,
message id, статья, политика источника, готовый текст или verdict из облака не принимаются.
Отдельной БД, файловой очереди или GitHub issues-очереди нет.

Далее вызывается существующий `server_runtime --submissions-only`: он обрабатывает
ограниченную штатную пачку предложки, включая ранее ожидающие обращения. Используется
обычный лимит обработки; при наличии более старого хвоста новая ссылка может остаться
до следующего штатного цикла. Source allowlist, независимое получение полного текста,
freshness, deterministic/event dedup, facts/utility reviews, high-risk owner review,
повторная сверка evidence и transport guards сохраняются. Неизвестная ссылка остаётся
кандидатом `waiting_primary`, а не авторитетным источником. Облачные кандидаты никогда
не получают приватных Telegram-ответов.

Повтор URL после удаления tracking query/fragment возвращает ту же Submission, не
сбрасывает её результат и не запускает worker повторно, если вся пачка уже принята.
Это не запрещает прежнему штатному циклу обработать ожидающие строки. Изменения
источника проходят существующий source-revision механизм; повторный intake не
перезаписывает evidence, редакционную работу или sent/sending/uncertain.

## Квитанция

Результат сохраняется в закрытом `editorial-state/state/current.json` →
`last_discovery` только вместе с каноническим checkpoint после успешной записи и
проверки Drive. Он содержит созданное количество, exit code обработки, candidate
keys, submission/raw IDs, наблюдаемые состояния и сохранённые Telegram message IDs.
`run_id` и `batch_sha256` связывают квитанцию с запуском и JSON принятой пачки.
`runtime_exit_code=0` сам по себе не доказывает публикацию. Публикация подтверждается
только delivery `sent` с message id; `pending`, `sending`, `uncertain` не означают успех.
Квитанция описывает последнюю пачку; повтор dispatch безопасно перечитывает её строки.

При сбое модели с обычным exit code принятые строки сохраняются и остаются для
следующего цикла. После timeout/сигнала/ошибки checkpoint остаётся `busy`; автоматического
повторения отправки или разблокирования нет. Public Pages не получают входной JSON и
не служат квитанцией intake. Внешний поиск не должен считать интервал переданным до
подтверждения его кандидатов каноническим checkpoint.

## Эксплуатационный предел

Наличие этого входа в `main` не включает runtime. Нужны выполненные условия
[ACTIONS_RUNTIME.md](ACTIONS_RUNTIME.md): подтверждённая остановка всех прежних писателей,
свежий финальный snapshot с offsets/квитанциями, канонический указатель и отдельная
авторизация Drive/Gemini/Telegram на runner. Нельзя bootstrap-ить историческую БД,
придумывать подтверждение fencing или снимать busy ради успешного запуска.

На момент подготовки входа 26.10.2026 в репозитории отсутствует ветка
`editorial-state`; последние `Editorial Actions` пропущены. Подключённый к чату
GitHub не предоставляет action `workflow_dispatch`. Для фактической передачи из
облака также требуется разрешённая возможность вызова этого API либо доверенный
исполнитель с таким доступом. Эти два эксплуатационных условия не заменяются merge.
Не создавать временные push-workflows, issues или коммиты со списками новостей для
обхода недостающего доступа.
