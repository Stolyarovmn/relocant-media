# Временная редакция на SQLite

`source-health` каждые шесть часов собирает официальный `city_beograd_news`.
`daily-analysis` запускается вручную и готовит максимум пять ещё не проверенных
материалов за последние семь дней через Gemini. Telegram не вызывается.
Результаты модели — предварительная подготовка, а не независимое редакционное
одобрение и не разрешение публикации.

Оба процесса используют общий reusable workflow и одну очередь выполнения.
SQLite восстанавливается из последнего артефакта `editorial-sqlite` ветки main.
После обработки файл сохраняется даже при ошибке Gemini или сборщика.
При отсутствии предыдущего состояния после успешных запусков процесс останавливается,
чтобы не начать незаметно с пустой базы. Проверка целостности предшествует обработке.
Первый запуск нужно выполнять после слияния PR в main.

Артефакты хранятся до 90 дней, в пределах политики репозитория. Это временное
хранилище, не резервное копирование: перед удалением артефактов или длительной
остановкой скачайте последнюю базу. Удалённое/истёкшее состояние восстанавливают
вручную; автоматического отката на старую базу нет. Отчёт хранится 30 дней.
Доступ к базе соответствует доступу к артефактам Actions; в неё не записываются
API-ключи, Telegram-сессии или учётные данные.

Для локальной проверки задайте `APP_ENV=staging`,
`DATABASE_URL=sqlite:///state/editorial.sqlite3`, создайте каталог `state`, затем
запустите `python -m relocant_media.ops.actions_cycle`.
Для подготовки добавьте `--analyze` и настройте `GEMINI_API_KEY`.
PostgreSQL и его Alembic-миграции остаются основным вариантом постоянного хранения.
SQLite инициализируется по текущим моделям; изменение схемы потребует отдельного
пути миграции перед последующим запуском.
