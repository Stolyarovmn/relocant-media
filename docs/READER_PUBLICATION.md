# Разрешение и подпись читателя

Версия reader-publication-2026-11-18-v1. Быстрый приём Vercel использует одинаковый
сценарий в чате бота и сообщениях каналу. ФИО, email и телефон не запрашиваются:
пожелание владельца18ноября2026. Публичное обозначение получателя — редакция
Relocant Media; контакт — действующий бот.

Это конкретное редакционное разрешение, а не заявление о полном соответствии
всем юридическим требованиям. Полная лицензия и документы об обработке данных
из READER_RIGHTS_PROPOSAL.md остаются проектом. Наличие только псевдонима не
исключает применимость законодательства о данных. Тема канала и гражданство
владельца сами по себе не выбирают единственную юрисдикцию.

## Сценарий

Обычная инструкция и сбор всех сообщений/файлов сохраняются. Для «Предложить новость»:

1. «Мой материал» / «Есть разрешение автора» / «Чужой источник».
2. Точный текст разрешения и канал → «Разрешить публикацию» / «Только для редакции».
3. «Без подписи» / «Мой @username», когда он есть / «Имя / псевдоним».
4. Имя или ник показываются дословно и отдельно подтверждаются перед публикацией.
5. Резюме, число сообщений и файлов → отправить, изменить разрешение/подпись,
   дополнить или отменить.

Жалобы, вопросы, исправления и деловые обращения не запрашивают разрешение на
публикацию. Чужой источник не считается разрешением автора; такой файл остаётся
только редакции. Телефон, имя и фото профиля в пост не подставляются.
Собственный материал получает «Фото: …» / «Видео: …»; для уполномоченного
отправителя — «Прислал: …», что не заменяет проверку прав исходного автора.
Анонимность означает отсутствие публичной подписи, а не отсутствие внутреннего
контакта для ответа. Подпись хранится отдельно от текста новости.

Разрешение относится к конкретному содержимому и текущему каналу, без рекламы,
продажи и автоматического распространения на другие каналы. Хранятся текст,
версия и SHA условий, scope, fingerprint содержимого, сообщения/время выбора
разрешения, отдельного подтверждения подписи и окончательной отправки.
Редактирование/добавление материала до отправки возвращает к подтверждению.
После отправки дополнение сохраняет номер, но его новый fingerprint не получает
прежнего разрешения и одобрения: редактор видит необходимость нового согласования.
Для повторного согласования читатель может отправить новый комплект отдельным
обращением с прежним номером в описании; изменение выбора по старой заявке пока
обрабатывается редактором по ответу читателя, без выдуманного автоматического согласия.

## Ручная проверка файлов

Для подтверждённого варианта «Чужой источник» с HTTPS-ссылкой редактору доступна
кнопка «Проверить первоисточник». Она переводит сигнал в обычную проверку
публичного источника с сохранением номера заявки. Допускаются только исходные
ссылки точной версии материала; новые сообщения требуют нового решения.
Частный текст и файлы не становятся доказательствами или публикационным пакетом.
Разрешение остаётся «только для редакции», одобрение файлов не возникает.
После подтверждённой публикации независимо подготовленной новости автор получает
ссылку штатным механизмом разрешения заявки. Само нажатие ничего не публикует.
Прямые ссылки на зарегистрированные СМИ разрешаются и в режиме предложки:
выключение массового сбора лент не исключает их из реестра доверенных адаптеров.
Сохраняются лимит десяти ссылок, запрет приватных поисковых запросов и все проверки.
Если ссылка временно не связалась, редактор может повторить её проверку той же
кнопкой после устранения причины: номер и закрытые материалы сохраняются,
повторное событие не создаётся и редакционные допуски не сбрасываются.
Явное действие точного владельца создаёт новую ограниченную серию из трёх попыток.
Без нового решения редактора лимит сохраняется между Actions-запусками; правки
читателя его не обнуляют. Для уже связанного, но ещё не разобранного документа
действует тот же повтор. Наличие редакционного решения или квитанции отправки
блокирует такую кнопку, включая состояния sending и uncertain.
Ручная проверка публичной ссылки использует отдельную очередь workflow, чтобы
не ожидать паузу автоматической цепочки. Общая блокировка канонического состояния
и запрет параллельного писателя сохраняются.

Для заявки «Чужой источник» без прямой ссылки на статью в реестре действует
автоматический поиск в плановом редакционном цикле. Текст сравнивается только
локально. Совпадения по названию и дате с публичными постами ставятся первыми
в ограниченный поиск по настроенным площадкам. В запросы попадают сведения
из публичных постов. При единственном совпадении с независимо собранным
официальным анонсом к заявке привязывается этот анонс и начинается обычная
редакционная проверка. Для совпадения нужна одна явная дата выпуска события.
Несколько подходящих официальных материалов требуют уточнения.

Если читатель переслал сообщение из публичного канала Telegram, предложка
сохраняет ссылку из системных данных пересылки. Имя отправителя пересылки и
сведения о закрытом канале в ссылку не входят. Цикл проверяет только каналы из
реестра города. Если сообщения нет в очередной публичной ленте, допускаются
до четырёх запросов точных публичных ссылок за цикл.
Заявку можно связать с независимо собранной статьёй, опубликованной по ссылке
из пересланного поста. Оригинал пересылки остаётся подсказкой для поиска.
Изменение ссылки проверяется вместе с изменением текста и вложений.

При ожидании подтверждения заявки перепроверяются в плановых циклах с интервалом
от шести часов. Если в течение 48 часов с приёма подтверждение не найдено,
бот закрывает заявку и сообщает причину автору после выполненной проверки.
Разрешение на материалы читателя, проверки фактов и карты при этом действуют
в обычном порядке. Механизм использует источники из реестра города.

Принятый материал попадает в каноническую очередь reader_review и закрытую карточку
редактора. Это касается и красивых фото без ссылки на официальный первоисточник.
Автоматический поиск первоисточника не подменяет проверку присланного файла.

Редактор получает файлы кнопкой «Вложения», просматривает содержание и принимает
решение «Содержание вложений проверено» либо «Отклонить вложения».
Проверяются обнажённые люди, жестокие сцены, прочее недопустимое содержание,
происхождение, права и сведения, раскрывающие автора/других людей.

Одобрение доступно только точному владельцу из его приватной карточки и после
подтверждённой доставки всех файлов. Оно привязано к fingerprint, записывается
только в каноническом обработчике и не может импортироваться из Vercel как факт
человеческой проверки. Правка материала делает прежнее одобрение непригодным.
Ручная проверка содержания не заменяет фактчек, права и редакционное решение.
Она сама ничего в канал не отправляет.

Закрытая карточка получает устойчивое целевое состояние: пустая клавиатура.
Если Telegram не подтвердил её снятие, следующий обработчик повторяет только
это идемпотентное редактирование с паузой, не итоговый ответ читателю.
«Сообщение не изменено» подтверждает уже достигнутое состояние.

Нормальная доставка пакета с _reader_submission_id проверяет связь с исходным
материалом, разрешение, подпись и точное одобрение файлов до claim/send.
public_reader_material — разрешённая публичная проекция без chat_id, user_id,
сведений профиля и закрытой переписки. Вложения не добавляются к публикациям
автоматически. Существующие проверки редакционного/медиапакета сохраняются.

## Сообщение читателя (запрос владельца 23.11.2026, #470)

Раньше разрешённый собственный материал оставался в `reader_review`: шлюз доставки
с `_reader_submission_id` существовал, но рабочий код не создавал такой выпуск.
Теперь каждый цикл (`materialize_reader_reports`) превращает до пяти подходящих
заявок в документ источника `reader_reports_<city>` (ownership `reader`,
source_type `reader_report`). Условия: «Мой материал» или «Есть разрешение автора»,
подтверждённое разрешение и подпись, не меньше 60 знаков текста без ссылок,
отсутствие телефонов и email, приём не старше 7 дней, не `test_only`.

Документ содержит только пометку «Сообщение читателя… Редакция его не подтверждала»,
текст заявки и выбранную подпись. chat_id, user_id и профиль не копируются.
`external_id = submission-<id>-<sha12>`, заявка переходит в `source_linked`,
поэтому существующий `reader_resolution` отвечает автору ссылкой на пост.

Обычный pipeline получает `reader_report=True`: отбор отклоняет рекламу, политику,
конфликты с частными лицами; черновик обязан атрибутировать сведения читателю.
Оба независимых ревью получают отдельное правило для `reader_reports_*`. Подпись
ставится детерминированно до ревью. `import_package` пишет `_reader_submission_id`.
Перед отправкой `reader_report_delivery_reason` сверяет документ с текущим
fingerprint заявки, требует атрибуцию («читател…») и отсутствие контактов.
Живой проверки страницы нет: документ привязан к закрытой заявке.

`reader` засчитывается первичным основанием только для city, culture, events, sport.
Остальные категории получают `reader_report_requires_review` — решение владельца с
готовым черновиком; его одобрение допускает сообщение вне высокорисковых тем.
Неодобренные файлы больше не блокируют текст: `public_reader_material` отдаёт их
только после точного одобрения владельца; заявка из одного фото ждёт его.

`editorial_cycle_observation` показывает `reader_submissions_30d`: только счётчики
по статусу, принадлежности, разрешению и исходу.

## Повторяемость и ограничения

Профиль условий: domain/reader_publication_v1.json и его копия в приёмнике.
Тест требует полного совпадения. Новый канал требует отдельного профиля/версии:
старое разрешение на него не переносится.

Автотесты: оба входа, три подписи, private/source, исправления и новые файлы,
отсутствующий username, старые кнопки, импорт/повтор, невозможность облачного или
чужого одобрения и блокировка рабочей доставки до ручного контроля.
Тесты не отправляют сообщения в рабочий Telegram.

Юридическое предположение о полной достаточности такого интерфейса не делается.
Функциональный выбор и доказательства действий внедрены; окончательные сведения
о физическом лице и правовая редакция документов не подменяются выдуманными данными.
