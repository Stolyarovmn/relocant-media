# Выбор обложки как часть редакционного цикла

Короткая новость получает максимум одну подходящую реальную обложку по умолчанию.
Генеративные изображения, которые пытаются изобразить событие, человека или место,
для новостных публикаций не используются. Если у проверенного первоисточника нет
подходящего изображения с подтверждаемым происхождением и основанием использования,
публикация может остаться текстовой либо получить **собственную детерминированную
информационную карточку**. Такая карточка не содержит чужих image bytes и не изображает
само событие: только абстрактный символ редакционной категории и узор, связанный с SHA
уже независимо проверенного editorial package. Она не заменяет source/evidence review.

## Два визуальных режима

Обычная текстовая публикация может попросить Telegram показать большую link-preview
картинку **того же проверенного первоисточника**, URL которого скрыт за короткой ссылкой
`Источник`. Bot API получает точный source URL через `link_preview_options.url` и
`prefer_large_media=true`; если Telegram или сама страница не дают пригодного preview,
пост остаётся текстовым. Это не image generation и не загрузка чужого файла в наш канал.
Preview не выставляет `rights_verified`, не превращает картинку в `MediaAsset` и не
заменяет редакционную проверку источника.

Полноценное вложение через `sendPhoto`/альбом — отдельный, более строгий режим. Локальные
байты допускаются только после source-specific discovery, проверки соответствия события,
основания использования, атрибуции и двух независимых media reviews. Наличие картинки
в link preview не даёт разрешения скачать и переопубликовать её как вложение.

Для безопасного fallback существует `origin=self_authored_card`. Команда
`relocant-media-card` создаёт PNG только из нашей графики и метаданных уже проверенного
пакета, сохраняет SHA256 и explicit `rights_basis`, но оставляет
`publication_permitted=false`. Карточка затем проходит тот же frozen media context и
**два независимых media-review**, что и реальная фотография. Генератор не создаёт review,
не устанавливает release в production inbox и не обращается к Telegram.

Последовательность для проверенного вложения: первоисточник → обнаружение основных
изображений → визуальная классификация и совпадение события/года → оценка основания
использования → выбор формата → скачивание снимка с SHA256 → два независимых
медиа-ревью → MediaRelease с атрибуцией → fake-проверка. Обнаружение картинки само по
себе никогда не выставляет `rights_verified=true` и не разрешает публикацию файла.

Если безопасного внешнего изображения нет, альтернативная последовательность:
проверенный editorial package → `relocant-media-card` → собственный PNG + assets manifest
→ freeze review context → два независимых media-review → MediaRelease. В этом пути
`rights_verified=true` относится только к доказуемому факту нашего собственного создания
карточки и никогда не выводится из source URL, `og:image` или чужой атрибуции.

## Generic source-page candidate extraction

`collectors/article_media.py` разбирает **уже загруженную** HTML-страницу проверенного
первоисточника. Этот слой сам не открывает произвольные URL, не использует web search и
не скачивает найденные в поиске изображения. Он предназначен для automatic candidate
extraction перед существующими cover selection и media review.

Из `<article>` (или `<main>`, если article отсутствует) извлекаются обычные и lazy-loaded
`img`, а из metadata — `og:image`, `og:image:url`, `twitter:image` и
`twitter:image:src`. Relative URL нормализуются относительно source page. Допускается
только HTTPS и только тот же image-host либо CDN, явно переданный вызывающим кодом в
allowlist. Credentials, нестандартные порты, HTTP/data/blob URL и изображения с
посторонних хостов отбрасываются. Очевидные logo/icon/avatar/sprite/tracker/pixel и
объявленные tiny images также не становятся кандидатами.

Для каждого кандидата сохраняются source page URL, direct image URL, способ обнаружения
(`origin`), alt, явная атрибуция из `figcaption`, `provenance_basis`, объявленные размеры,
`rights_hint` и `event_match=unreviewed`. Наличие `og:image`, подписи автора или размещение
на официальном домене **не** означает пригодность к публикации и никогда автоматически
не подтверждает права или совпадение с событием.

После редакционного выбора helper скачивания повторно проверяет каждый redirect и
allowlist, ограничивает ответ 10 МБ, принимает только JPEG/PNG по сигнатуре и сохраняет
SHA256 фактически полученных байтов. Хэш фиксирует конкретный asset, но не является
основанием использования. Source-specific adapters ниже остаются предпочтительнее там,
где структура официального сайта уже известна: их ограничения точнее generic parser.

## Реализованные адаптеры

### Чукарица

Извлекается только Featured Image основной статьи, без footer, логотипов,
связанных новостей и произвольного og:image. HTTPS, домен и путь загрузок проверяются
перед каждым переходом; размер ограничен 10 МБ, формат определяется по байтам.

### Grad Beograd / beograd.rs

Для поддерживаемых `beoinfo-vesti` и сервисных статей извлекаются только реальные
article-level изображения с официального `static.beograd.rs`. Допустим путь вида
`/api/v3/images/<numeric-id>/<medium|large|original>`; сторонние хосты, UI-иконки,
логотипы, неизвестные пути и credentials отбрасываются. Публичный URL статьи и точный
URL изображения сохраняются в manifest; скачанный файл именуется по SHA256.

На живой статье 16.10.2026 проверен текущий шаблон: hero-фото статьи отдаётся через
`static.beograd.rs/api/v3/images/...`. Адаптер сохраняет доступную подпись/credit, но
не превращает её в разрешение. Условия beograd.rs отдельно предупреждают, что часть
фотографий и другого контента защищена авторским правом; свободное повторное использование
касается только материалов без прав третьих лиц и требует указания источника. Поэтому
`rights_hint` служит лишь подсказкой для review, а не автоматическим юридическим выводом.

```sh
APP_ENV=staging python -m relocant_media.ops.cover_cli \
  --article-url https://www.beograd.rs/lat/beoinfo-vesti/a116251/...html \
  --output /new/run/discovery
```

`cover_cli` сам выбирает поддерживаемый source-specific adapter. Команда не использует
Telegram, AI API, токены или `.env`. Первый manifest содержит кандидатов, точные source
URLs и `generated_media_used=false`, но не автоматическое заключение об их правах.
Исходная HTML-страница сохраняется рядом с manifest.

Редакционный агент просматривает изображение, сверяет его с событием и заполняет
массив `CoverAssessment` в отдельном JSON. Поля описаны в
`services/cover_selection.py`. Для основания использования сохраняются метод, URL
доказательства, объяснение, статус оценки и роль оценившего. «Официальный сайт» —
происхождение, не лицензия. Явное стороннее авторство требует отдельного review.

```sh
python -m relocant_media.ops.cover_cli --article-url <тот же URL> \
  --assessments /run/assessments.json --event-year 2026 --output /new/run/selected
```

Оценки связываются с обнаруженными URL и конкретной статьёй. Скачиваются только
выбранные материалы. `publication_permitted=false` остаётся в manifest: выбор
обложки не заменяет проверку готового текста и самих байтов двумя рецензентами.

## Собственная fallback-карточка

Карточка создаётся только для уже `ready`/`pending` production run с сохранённым и
совпадающим `_package_sha256`. Генератор читает категорию и HTTPS первоисточник из этого
пакета; произвольные title/source параметры с CLI не принимаются. Так карточку нельзя
оторвать от конкретного independently reviewed выпуска.

```sh
APP_ENV=production DATABASE_URL=sqlite:////var/lib/relocant-media/editorial.sqlite3 \
  relocant-media-card --raw-item-id 123 --output /review/generated/123
```

Выход содержит `assets/self-authored-card.png`, минимальный `assets.json` для обычного
media release prepare и отдельный `generation.json` с package SHA, source URL, asset SHA
и явными флагами `third_party_image_bytes_used=false`,
`requires_independent_media_reviews=true`, `publication_permitted=false` и
`telegram_io_performed=false`.

PNG строится локально детерминированно и не загружает картинку из source page. Поэтому
`rights_verified=true` в этом **единственном** случае подтверждает наше авторство байтов,
а не права на сторонний материал. Source URL остаётся provenance фактов выпуска и должен
быть credential-free HTTPS. Дальше используется обычный `relocant-media-release prepare`;
без двух свежих совпадающих reviews `release.json` не появится.

## Правила выбора

- Реальная афиша текущего события с подтверждённым соответствием — первый кандидат.
- Затем подходящее фото текущего события; архив требует известного года и подписи.
- Изображение из чужого Telegram-канала не переиспользуется автоматически. Каналы
  служат discovery-сигналом; медиа нужно независимо проследить до первоисточника и
  проверить права/атрибуцию.
- Неизвестный тип, несовпадение события/года, логотип или незавершённая оценка прав
  не дают внешнюю обложку. Решение без чужой картинки не блокирует редакционный текст.
- Собственная fallback-карточка не маскируется под фотографию события и не содержит
  новых фактических утверждений; её media-release всё равно требует два review.
- Альбом возможен только с `--allow-album`, минимум двумя снимками с отдельной
  визуальной пользой; максимум пять. Само количество доступных картинок не аргумент.
- Афиша сохраняется целиком. Не удаляйте логотипы, автора и существенные условия.

Для `MediaAsset` поддерживается `origin=official_poster`; фото продолжают проходить
существующий review-bound media pipeline. Штатный сервис принимает исходный проверенный
текст плюс точные атрибуции/архивные подписи из assets; произвольный новый текст этим
путём не проходит. Вся подпись и метаданные связаны с двумя медиа-ревью.
См. [EDITORIAL_MEDIA.md](EDITORIAL_MEDIA.md) для пакета и доставки.
