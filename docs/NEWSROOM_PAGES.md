# Операционная витрина на GitHub Pages

`web/newsroom` — read-only панель двух городов. Реестр и фактическое состояние БД
показаны раздельно. Нови-Сад не наследует данные Белграда. `null` означает отсутствие
наблюдения, а не нулевые результаты. Снимок старше 6 часов получает предупреждение;
пересборка Pages не обновляет время наблюдения БД. Браузер перечитывает JSON каждую минуту.

## Почему облачные черновики не прошли автоматические проверки

Облачная задача в чате не является серверным `server_runtime`. Её текст не создаёт
`RawItem`/`EditorialRun`, пакет evidence, подписи двух ревью и квитанции. Поэтому обычные
серверные проверки не запускаются на ответе чата. Для выпуска материал должен попасть
в существующий ingestion/prepare/review/import/delivery путь. Нельзя проставить `ready`
на основании ответа чата или создать вторую production-БД.

## Обновление после каждого серверного цикла

`deploy/server/run-cycle.sh` после успеха ИЛИ ошибки редакции вызывает
`newsroom_after_cycle`. Тот читает существующую SQLite из `DATABASE_URL` через `mode=ro`
и `PRAGMA query_only`, создаёт `newsroom-public.json`, затем при наличии отдельного
`NEWSROOM_GITHUB_TOKEN` выгружает его в `dashboard-data/latest.json` ветки
`newsroom-data`. Это запускает `Newsroom Pages`. Исходный статус редакционного процесса
сохраняется. Ошибка обновления витрины записана отдельно в `newsroom-refresh.json` и stderr;
она не меняет отправки и не вызывает повторную публикацию.

Владелец на сервере задаёт `NEWSROOM_GITHUB_TOKEN` с правами Contents write только для
этого репозитория в существующем защищённом окружении systemd. Токен должен поддерживать
запуск workflow при push (PAT/GitHub App installation token; стандартный Actions GITHUB_TOKEN
не запускает последующие push-workflows). Не коммитить токен. Автоматическая задача не
создаёт и не меняет секрет. До настройки upload возвращает `credential_not_configured`.
После установки новой версии hook заработает при следующем естественном цикле;
не надо запускать редакцию ради установки сайта.

Workflow использует код/реестр из main и только снимок данных из newsroom-data.
Сам снимок не меняет код и source/editorial policy. Ветка данных первоначально создаётся
из main; её код не исполняется workflow. Конкурентные записи защищены contents SHA:
конфликт считается ошибкой, снимок не перезаписывается force-push.

Для первоначального включения Pages нужна однократная настройка
Settings → Pages → Source: GitHub Actions. Workflow не пытается менять настройки
репозитория с недостаточными правами. До шага Pages сохраняется артефакт
`newsroom-preview`, доступный для проверки даже при ошибке развёртывания.
Не выдавать зелёный CI за успешный Pages deployment.

## Экспорт и приватность

Публичны: реестр, статусы/коды причин, IDs событий и квитанций, даты, ревью, журнал
вызовов моделей и вероятности shadow Jev. Нет текстов черновиков/доказательств,
обращений, пользователей, приватных контактов, сообщений исключений, токенов.
Заголовки показываются только для `ownership=official`; остальные скрыты.
Свободный текст reason заменяется безопасным кодом. Полная операторская работа
с приватными материалами остаётся в защищённом контуре; GitHub Pages — публичная витрина,
не система авторизации и не интерфейс для изменения состояния.

Атрибуция discovery-модели неизвестна, если нет сохранённой связи. Нельзя приписывать
сбор HTTP-коллектора Gemini или GPT. Существующие AIUsageEvent показываются отдельно;
server-cycle дополнительно экспортирует task/provider/model/status из ai-calls.jsonl
(новые записи включают явную модель). GPT из чата не считается серверным вызовом.
Jev показывает shadow-сигналы из manifest, никогда не authoritative approve/reject.

Локальный просмотр без доступа к БД:

```bash
python -m relocant_media.ops.newsroom_export --output web/newsroom/data.json
python -m http.server --directory web/newsroom 8080
```

Для полного локального снимка добавить `--database /absolute/path/to/existing.sqlite`.
Отсутствующая БД — ошибка, новая БД не создаётся. Не публиковать исходную SQLite,
`server-report.json`, `package-*.json` или сырые логи на Pages.
