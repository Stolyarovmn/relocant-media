# Пропуски тем, задержки и граница инструкций

## Назначение

Публичная документация описывает механизм отбора и диагностический интерфейс.
Результаты анализа конкретной рабочей очереди, её внутренние идентификаторы,
состояния писателя и закрытые снимки в репозиторий не добавляются.

## Изменения

- Основной текст и исходящие ссылки Telegram выбираются из одного блока сообщения;
  reply-цитаты и предпросмотры ссылок исключены. Подписи альбомов и старая разметка
  поддерживаются регрессионными примерами.
- `cities/belgrade/queue-locality.json` содержит явно проверенные варианты места
  Knez Mihailova. Он меняет только порядок рассмотрения; не факты, источник,
  категорию риска или допуск. Хеш редакционного профиля не меняется из-за этих подсказок.
- Отбору явно объяснено: текущее подтверждённое предупреждение о задержках или
  наземном обслуживании не требует известных номеров всех рейсов. Общая погодная
  заметка без предупреждения о текущем сбое не получает этот аргумент автоматически.
- В разрешении публичной темы сохраняются отдельные `discovery_gaps`:
  `outbound_url_not_supported` — нет поддерживаемого пути для этой ссылки (домен или URL);
  `no_configured_search_plan` — нет настроенного плана поиска;
  `search_budget_exhausted` — исчерпан общий бюджет;
  `search_already_attempted` — этот поиск уже выполнялся в цикле;
  `search_without_accepted_match` — поиск не дал принятого совпадения.
  Эти коды не расширяют allowlist; неизвестные URL/тексты не добавляются в доказательства.
- Версия матрицы подачи `ru-local-news-v4` передаёт общую границу процедур автору,
  исправлению, резервному пакету и двум независимым проверяющим.

Изменение не создаёт второго writer и не меняет маршрутизацию или расписание.
Ожидание резервного процесса не означает выполненную резервную проверку.

## Что редакция может сообщать

1. **Уведомление.** Кто объявил изменение, кого оно прямо касается, когда действует,
   где официальный текст/запись. Ссылка на запись не доказывает свободный слот,
   право каждого читателя на услугу или результат обращения.
2. **Общая официальная инструкция.** Пересказ только явно действующих требований
   первоисточника с адресатами, условиями и исключениями. Нельзя достраивать шаги,
   документы, поля формы или применимость из знаний модели, чужого опыта и неполных
   пересказов. В новостном канале нужен подтверждённый новый повод.
3. **Индивидуальный совет.** Выбор варианта за человека, заполнение его банковского,
   правового, миграционного, налогового или медицинского документа, вывод о личном
   праве на выплату/разрешение — не задача автоматической редакции. Личные документы
   и реквизиты у читателя не запрашиваются.

Два LLM-ревью не заменяют эксперта и не гарантируют распознавание каждого смыслового
риска. Banking/law/immigration/tax/medicine сохраняют human_review даже у короткого
официального уведомления с двумя approve. Подозрительная инструкция в низкорисковом
анонсе также требует hold/reject. Дисклеймер в конце не исправляет неподтверждённое
утверждение в основном тексте.

Не все отсутствующие публикации являются ошибкой. Нет требования копировать
политическую, криминальную и банковскую ленту LIVE или превращать архивную памятку
в новость. Сравнение каналов даёт темы для проверки, не первичные доказательства.

## Повторная диагностика

После штатного получения проверенного immutable snapshot создайте JSON-массив
`[{"label":"Название случая","urls":["https://known.example/article"]}]`.

```sh
python -m relocant_media.ops.coverage_audit \
  --database /private/verified/editorial.sqlite3 \
  --cases /private/cases.json \
  --observed-at 2026-01-01T12:00:00+00:00 \
  --output /private/new-audit.json
```

Команда не открывает runtime settings, не обращается к сети, не загружает ключи,
не пишет в SQLite и не вызывает Telegram. Она разделяет published, selection_rejected,
review_hold, processing_failed, collected_without_decision. Исследуются точные URL
после удаления tracking-параметров; отсутствие URL не доказывает отсутствие темы.
`first_decision_record_at` — создание первой строки решения, не время замены текущего
outcome при повторном импорте. Время доставки приводится отдельно; неизвестное время
повторного решения не восстанавливается из догадок.
Отчёт не содержит тело статьи, частные заявки или персональные документы.

## Эксплуатационная проверка

Обязательные ruff/mypy/pytest и CI main должны пройти до заявления о выпуске.
Windows не содержит fcntl и POSIX interval timers: полный набор проверяется в Linux CI.
Новый отбор требует наблюдения следующих штатных циклов: тесты подтверждают механизм,
а не гарантируют публикацию конкретной темы или достижение заданного времени.
Архивные отказы/квитанции не сбрасываются, вчерашние сообщения повторно не отправляются.
Новые адаптеры и дополнительные разрешения категорий этим изменением не включаются;
неподдерживаемый URL получает явную диагностическую причину.
